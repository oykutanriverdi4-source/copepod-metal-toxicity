# Integrated local correction — 7 October 2026

## Scope
This is the integrated **source and reporting correction**. It is suitable for a local verification run, not a declaration that all thesis/source-quality questions have been resolved or that a new archive has been published. Original inputs and model definitions are retained except for the previously source-verified C6 label and O'Brien annotation correction.

Changed existing scripts: `00_run_core_pipeline.R`, `04_fit_pooled_metal_model.R`, `09_compare_stages_within_references.R`, `10_audit_stage_support.R`, `11_fit_stage_model.R`, and `13_fit_order_model.R`. A reporting helper and synthetic reporting tests are new.

The figure-generation script `scripts/figures/01_make_main_thesis_figures.R` is **unchanged for this correction**. Its numerical inputs and preserved column/object names remain available. It must run after the new analyses. The existing 19-figure suite is regenerated, including stage-dependent Figures 4.7, 4.8, 4.9 and 4.16; model diagnostic plots are regenerated by their model scripts. This is not a completed visual audit of the new images. Any later caption/layout revision is a separate documented change.

## Run
Copy the contents of DEGISTIR_EKLE into the local project, preserving the directory structure, after making a separate full-project backup. Open the project's Rproj and use:

```r
source("RUN_REVISION.R", encoding = "UTF-8")
```

The launcher starts a separate Rscript process from the current R installation with --vanilla, passing the current library search paths. It does not restore saved workspaces, install packages, call Git, or contact an archive. The run starts by checking source/input fingerprints, parsing R scripts, and executing reporting tests.

Before generating outputs it moves the 01–16 core output folders, the core run folder, `results/figures`, and the two canonical processed CSVs to a newly named **sibling backup directory outside the project**. No raw/curated input, optional database-audit folder, .git directory, or source code is moved by the runner. This prevents old output files or completion markers from masquerading as newly produced files. A list of moved paths is saved in that backup. If moving a path fails, the run stops and reports which paths have already moved. The separate full-project backup remains the easiest rollback.

### Why the processed CSV is rebuilt from scratch
Script 01 includes an optional strict comparison with any pre-existing canonical CSV. An old CSV correctly differs from the intentional C6/annotation correction and would fail that comparison. The runner therefore preserves that old CSV in the backup, rebuilds without an old canonical target, and performs an explicit post-run comparison that permits **only** the documented C6 life-stage and O'Brien Harmonization_Rule changes. It does not silently ignore other record/value changes. All existing raw-data, ledger and numerical checks in Script 01 are retained.

## Outputs and reporting
The underlying 00 runner executes 01–15 and the existing figure script. Updated outputs are generated on the user's computer, not supplied as stale files in this patch. The new local `REVISION_CHECK.txt` records success or the failed stage; `REVISION_CONSOLE.log` retains console output. These two files can contain workstation paths and are excluded by the updated .gitignore. Other core outputs include reporting_unit_tests.csv and the explicit source-correction dataset checks.

The numerical checks are regression checks for this correction, not tests of the full biological validity of the models. R execution, new output values, new figure rendering and final archive consistency require review after the local run.

## Unchanged or still open
The current patch does not implement new weighting, a new Cr inclusion rule, new genera exclusions, or a new modelling strategy. Source reliability/precision coverage, Cr basis, genus sensitivity and complementary evidence reviews remain open as recorded in the thesis tracker. Word/Discussion/Abstract/Conclusion edits are not included. DOI/version/date fields in CITATION.cff are not changed here; they must be reconciled with the actual eventual archive. No archival decision is made by running this patch.

The README now explicitly labels this working correction as unarchived; its existing DOI citation identifies the previous release, not newly generated results.
